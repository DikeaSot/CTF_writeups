We are given an image containing a sequence of symbols. The description mentions:

>*some old technology type of thing*

Since this is a crypto challenge, this strongly suggests that the symbols represent some kind of classical or historical cipher.

The first step is therefore to identify the cipher used in the image.

Searching for symbol-based ciphers led to a useful page: https://decipher.wiki/symbols-list <br>
Browsing through the list of symbol ciphers reveals that the symbols in the image match the <u> Pigpen cipher </u>, also known as the Masonic cipher.<br>
The Pigpen cipher is a simple substitution cipher where each symbol corresponds to a letter of the alphabet.

<img src="./images/pigpen_cipher.png" alt="pigpen" width=500>

Using the Pigpen cipher reference, we can [decode](https://crypto.interactive-maths.com/pigpen-cipher.html) each symbol into letters.
After decoding and preserving the original spacing from the image we get: 

```ddd c fff ff h ee ff fff i ddd ccc h dd ddd gggg bbb ddd g dd cc ggg ddd gggg ggg cc b eee```

<img src="./images/decryption.png" alt="decryption" width=700>

At this stage, the output doesn't seem to be the plain text we want so an additional decoding step is likely required.

The hint *old technology* suggests that the decoded text might relate to an older communication method. <br>
One idea was that the letters might represent segments in a [7-segment display](https://www.geeksforgeeks.org/digital-logic/bcd-to-7-segment-decoder/). However, this assumption was quickly discarded because the sequence contains leters like ```h``` and ```i```, which don't correspond to 7-segment labels.

Another idea was to convert the letters into their alphabetical positions:

``` 
a = 1
b = 2
c = 3
d = 4
e = 5
f = 6
g = 7
h = 8
i = 9
```

Applying this transformation we get: 

```444 3 666 66 8 55 66 666 9 444 333 8 44 444 7777 22 444 7 44 33 777 444 7777 777 33 2 555```

This number pattern resembles the [multi-tap input method](https://en.wikipedia.org/wiki/Multi-tap) used on old mobile phones, where each number key corresponds to several letters and pressing the key multiple times selects a specific character.
Using this observation, the sequence of numbers can be interpreted as multi-tap input. To test this assumption we look for an [online decoder](https://www.dcode.fr/multitap-abc-cipher) and eventually we manage to get the plaintext: ```IDONTKNOWIFTHISCIPHERISREAL```
